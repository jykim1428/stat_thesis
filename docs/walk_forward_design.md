# Walk-Forward Validation 설계

## 배경

기존 파이프라인은 국면(regime) 단위의 고정 분할을 사용한다 (`data/processed/regime_definition.csv` 참조).

| 국면          | 기간                      | 기존 split |
| ----------- | ----------------------- | -------- |
| bull_2021   | 2021-01-01 ~ 2021-11-09 | train    |
| bear_2022   | 2021-11-10 ~ 2023-01-01 | train    |
| side_2023   | 2023-01-02 ~ 2023-10-15 | val      |
| bull_2024   | 2023-10-16 ~ 2025-01-01 | test     |
| choppy_2025 | 2025-01-02 ~ 2025-12-31 | test     |

시계열 데이터의 시간 순서와 국면 경계를 보존하기 위해 국면을 랜덤 셔플하거나 중간에서 임의로 분할하지 않는다. Walk-forward validation은 이러한 원칙을 유지하면서 학습 구간을 시간 순서대로 확장하고, 서로 다른 미래 시점의 out-of-sample(OOS) 성과를 평가하는 방식이다.

본 연구에서는 국면 수가 제한적이고 각 국면의 시간적 특성을 보존할 필요가 있으므로 **regime-preserving expanding-window 2-fold forward evaluation**을 사용한다.

## 설계 원칙

* **윈도우 방식:** Expanding window를 사용한다. 국면이 5개뿐인 상황에서 rolling window로 오래된 데이터를 제거하면 학습 데이터가 지나치게 감소할 수 있으므로, 과거 데이터를 누적하는 방식을 사용한다.
* **Fold 단위:** 국면 경계를 기준으로 fold를 구성한다. 국면 내부를 임의로 분할하지 않는다.
* **정책망 비교:** MLP와 Transformer는 사전에 비교 대상으로 고정한다. validation 결과에 따라 특정 정책망을 제외하거나 선택하지 않으며, 두 정책망의 OOS 성과를 모두 보고한다.
* **하이퍼파라미터 선택과 최종 학습의 분리:** Fold 1의 validation 구간에서 각 정책망의 하이퍼파라미터를 사전에 정의한 기준에 따라 선택한다. 설정이 확정된 이후에는 validation 구간까지 포함한 누적 학습 데이터로 최종 모델을 새로 학습한다.
* **평가 구간의 독립성:** 각 OOS 구간의 성과는 해당 OOS 구간을 사용하여 정책망 구조, 하이퍼파라미터 또는 실험 조건을 결정하지 않은 상태에서 계산한다.

## Fold 구성

| Fold | 하이퍼파라미터 선택                                   | 최종 학습 데이터               | OOS test                              |
| ---- | -------------------------------------------- | ----------------------- | ------------------------------------- |
| 1    | train: bull_2021 + bear_2022, val: side_2023 | 2021-01-01 ~ 2023-10-15 | bull_2024 (2023-10-16 ~ 2025-01-01)   |
| 2    | Fold 1에서 확정한 설정을 그대로 사용                      | 2021-01-01 ~ 2025-01-01 | choppy_2025 (2025-01-02 ~ 2025-12-31) |

## Fold 1 절차

1. 각 정책망과 사전에 정의된 하이퍼파라미터 후보를 `bull_2021 + bear_2022`에서 학습한다.
2. `side_2023` validation 성과를 사용하여 사전에 정의한 선택 기준에 따라 각 정책망의 하이퍼파라미터 설정을 선택한다.
3. 선택된 설정을 고정한 후 `2021-01-01 ~ 2023-10-15` 전체 구간을 사용하여 PPO를 새로 학습한다.
4. 최종 학습된 모델을 `bull_2024` (`2023-10-16 ~ 2025-01-01`)에서 평가한다. 이 결과를 Fold 1의 OOS 성과로 기록한다.

## Fold 2 절차 및 leakage 방지

Fold 2에서는 Fold 1의 OOS 구간인 `bull_2024`를 이후 시점의 평가 구간인 `choppy_2025`보다 과거에 관측 가능한 데이터로 간주하여 학습 데이터에 포함한다. 따라서 Fold 2의 학습 데이터는 `2021-01-01 ~ 2025-01-01`로 확장된다.

이 과정은 미래 정보 누수(leakage)에 해당하지 않는다. Fold 2에서 평가하는 `choppy_2025`는 시간상 이후에 위치하며, Fold 2의 학습 데이터에는 `choppy_2025`의 정보가 포함되지 않는다.

또한 Fold 1의 `bull_2024` OOS 성과 자체는 Fold 2의 정책망 구조, 하이퍼파라미터, 학습 기간 또는 실험 조건을 결정하는 데 사용하지 않는다. Fold 2에서는 Fold 1의 `side_2023` validation에서 이미 확정된 설정을 그대로 사용한다.

즉, Fold 2에서는 과거 OOS 기간의 **원시 관측 데이터가 이후 시점의 학습 데이터로 편입**되지만, 해당 OOS 성과를 이용한 모델 선택이나 하이퍼파라미터 재조정은 수행하지 않는다.

## Fold 2에서 별도 validation을 두지 않는 이유

`bull_2024` 국면의 일부를 별도의 validation 구간으로 분할하면 국면 단위로 전체 국면을 하나의 fold에 배정한다는 본 연구의 설계 원칙과 충돌한다.

따라서 Fold 2에서는 별도의 하이퍼파라미터 탐색을 수행하지 않고, Fold 1의 `side_2023` validation에서 확정된 정책망별 설정을 그대로 사용한다. 이를 통해 Fold 2의 `choppy_2025` OOS 구간이 추가적인 하이퍼파라미터 선택에 이용되는 것을 방지한다.

## TIME_WINDOW=50 워밍업 처리

본 연구의 데이터는 1시간봉이며 `TIME_WINDOW=50`을 사용하므로, 각 평가 구간 시작 직전의 **50시간 데이터**를 observation 워밍업에 사용한다.

워밍업 데이터는 실제 평가 구간에 진입하기 전에 관측 가능한 과거 데이터로서 observation을 구성하기 위한 목적으로만 사용한다. 실제 거래, reward 계산 및 성과 기록은 각 OOS test 구간의 시작 시점부터 수행한다.

따라서 test 구간 시작 시점에 생성되는 첫 번째 유효 observation은 test 시작 직전 50시간의 과거 정보를 포함할 수 있으며, 이는 미래 정보 누수에 해당하지 않는다.

구현 시 평가용 입력 데이터에는 test 시작 전 50시간을 포함하되, 백테스트 결과 CSV와 성과지표 계산에는 실제 test 시작 이후의 거래 결과만 남긴다.

## 지표 보고 방식

각 OOS fold에 대해 다음 지표를 계산하여 별도로 보고한다.

* Sharpe ratio
* Sortino ratio
* Calmar ratio
* Maximum Drawdown (MDD)
* Volatility
* CAGR
* Average Turnover
* Total Transaction Cost

두 OOS 국면의 성과를 단순 평균하여 하나의 성과로 제시하지 않는다.

또한 `bull_2024`와 `choppy_2025`의 실제 test 기간별 시간별 `returns`를 날짜순으로 연결하여 전체 OOS 구간의 성과지표를 별도로 계산할 수 있다.

이때 각 fold의 `reset()`에서 생성되는 초기 행은 실제 거래 수익률이 아니므로 전체 OOS returns 연결에서 제외한다. 날짜 중복이 없는 실제 test 기간의 returns만 시간순으로 연결하며, 각 fold에서 초기값으로 다시 시작하는 `portfolio_values`는 단순 연결하지 않는다.

## 알려진 한계

본 연구에서 사용할 수 있는 국면은 총 5개이며, OOS 평가에 사용할 수 있는 미래 국면은 `bull_2024`와 `choppy_2025`의 두 개로 제한된다. 따라서 본 검증은 일반적인 다중 fold cross-validation이라기보다 **regime-preserving expanding-window 2-fold forward evaluation**으로 해석해야 한다.

또한 Fold 2에는 별도의 validation 구간이 없으므로 하이퍼파라미터 설정은 Fold 1의 `side_2023` validation 결과에 의존한다. 따라서 Fold 2에서 새로운 하이퍼파라미터 탐색을 수행하는 것보다 보수적인 설계이지만, 다양한 시장 국면에서 독립적인 hyperparameter validation을 반복하는 구조는 아니다.

## 실행 개요

기존 `PortfolioOptimizationEnv` 및 백테스트/evaluate 파이프라인을 재사용한다. 다만 현재 `adapter.load_env_ready_df(split=...)`는 고정 split 라벨을 기준으로 동작하므로, fold별 누적 학습 및 OOS 평가를 수행하기 위해 날짜 범위 기반의 데이터 필터링 인터페이스를 추가한다.

모든 정책망에 동일한 다음 조건을 적용한다.

* Fold 경계
* 거래비용
* 초기 자본
* 관측 창(`TIME_WINDOW`)
* 보상 함수
* 평가 지표
* OOS 평가 절차

정책망 수를 `M`, 정책망별 Fold 1 하이퍼파라미터 후보 수를 `N`, 최종 학습의 seed 반복 수를 `S`라고 하면, 정책망 하나당 필요한 PPO 학습 횟수는 `N + 2`이며(Fold 1 후보 탐색 N회 + Fold 1 최종 재학습 1회 + Fold 2 학습 1회), 전체 학습 횟수는 `M × S × (N + 2)`이다.

컴퓨트 예산 산정(파일럿 측정, Colab 실행 단위, resume 원칙 등)은 별도 문서인 **`Colab 컴퓨트 예산 점검`** 문서를 따른다. 후보 수 `N`, seed 수 `S`는 해당 문서의 파일럿 측정 결과를 반영해 대량 실행 전에 확정한다.
