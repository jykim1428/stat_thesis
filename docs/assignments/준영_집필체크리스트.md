## 3.2 강화학습 환경 설계 (3쪽, 10/7)

> **가장 먼저 쓸 것.** 상태·행동·보상 기호가 확정돼야 3.3·3.5·3.6이 참조 가능.

### 3.2.1 상태·행동·보상

- [ ] 관측 텐서 **(3, 8, 50)** = (가격 피처 3, 자산 8, lookback 50시간)
- [ ] `TIME_WINDOW = 50`
- [ ] action shape **(9,)** = 자산 8 + 현금 1
- [ ] **action space `Box(low=-10.0, high=10.0)`** — ⚠️ `[0,1]`이 아닌 이유를
      반드시 서술: softmax 정규화 전 raw action이므로 범위 제약을 두면
      정규화 후 표현 가능한 비중 공간이 왜곡된다
- [ ] 비중 벡터 인덱스: **0=CASH, 1~8=ADA,AVAX,BNB,BTC,DOGE,ETH,SOL,XRP**
- [ ] `target_weights` (softmax 정규화 직후, 가격 변동 반영 전) vs
      `weights` (기말 실제 비중) **정의 구분** ← 3.2.2와 4.5가 전부 의존
- [ ] 보상 = **로그 수익률** `r_t = log(V_t / V_{t-1})`, `reward_scaling = 1`
- [ ] 초기 자본, 에피소드 구성

### 3.2.2 거래비용 및 turnover 처리

- [ ] `cost_rate = 0.001` (편도 0.1%)
- [ ] **turnover 정의 (핵심)**:
      `turnover_t = Σ|target_weights_t − weights_{t−1}| / 2`, t=0은 0
- [ ] **왜 이 정의인지 서술** — `Σ|weights_t − weights_{t−1}|/2`를 쓰면
      가격 변동에 의한 비중 변화까지 거래량으로 계상되어 거래비용이
      과대계상됨 (실측 약 1.2~1.45배)
- [ ] `net_return_t = gross_return_t − turnover_t × cost_rate`
- [ ] ⚠️ **버그 수정 이력으로 쓰지 말 것.** 정의를 명확히 서술하고, 흔한
      오류를 피했다는 형태로 (용어사전 §10-9)

**근거:** `env_portfolio_optimization.py`, `evaluate.py`, 용어사전 §3

## 3.5 Walk-Forward Validation 설계 (4쪽, 10/14)

> `docs/walk_forward_design.md`가 이미 논문 문체에 가깝다. 재배열 위주.

- [ ] 정식 명칭: **regime-preserving expanding-window 2-fold forward
      evaluation** / 국면 보존 확장 윈도우 2-fold 전진 평가
- [ ] ⚠️ **"교차검증"으로 쓰지 말 것** — k-fold CV가 아니다
- [ ] expanding window를 쓴 이유 (국면 5개뿐, rolling은 학습 데이터 과소)
- [ ] Fold 구성표 (용어사전 §5)
- [ ] **Fold 2의 leakage 통제** — `bull_2024`를 학습에 포함하는 것이 왜
      누수가 아닌지: ① `choppy_2025`는 시간상 이후 ② Fold 1의 OOS **성과**를
      Fold 2의 설정 결정에 쓰지 않음
- [ ] **Fold 2에 별도 validation을 두지 않은 이유** — 국면 단위 배정 원칙과
      충돌하기 때문. 더 보수적인 설계임을 명시
- [ ] **워밍업 50시간** — 관측 구성에만 사용, 거래·보상·성과 기록은
      OOS 시작부터. 누수가 아닌 이유
- [ ] OOS 스텝 수: 상승 10,656 / 조정 8,713
- [ ] `choppy_2025` 실제 종료 **2025-12-31** (명목 상한 2026-01-01 아님),
      모든 전략에 동일 적용
- [ ] 한계 명시: OOS 국면 2개뿐, Fold 2는 Fold 1 validation에 의존

## 3.6 평가 지표 및 통계적 유의성 검정 (3쪽, 10/14)

### 3.6.1 성과 평가 지표

- [ ] 지표 8종 정의 (Sharpe/Sortino/Calmar/MDD/Vol/CAGR/turnover/총비용)
- [ ] **연율화 상수 8,760 (=24×365)** — 1시간봉이므로 252가 아님
- [ ] `risk_free = 0`
- [ ] **모든 모델·벤치마크가 동일 함수(`evaluate.py`)로 평가됨** ← 원칙으로 서술
- [ ] **전 지표 net 기준** 보고
- [ ] ⚠️ **Sharpe > 0인데 CAGR < 0인 경우** 설명 (산술 vs 기하평균) —
      4.3에서 쓰기 전에 여기서 정의해두면 깔끔
- [ ] quantstats는 참고용(non-canonical)임을 각주로

### 3.6.2 Stationary block bootstrap

- [ ] `arch.bootstrap.StationaryBootstrap`
- [ ] 블록 크기 **24시간**(주), **168시간**(민감도)
- [ ] 리샘플 **2,000회**, 신뢰수준 95%
- [ ] 통계량: `mean_seed[Sharpe(PPO_seed) − Sharpe(benchmark)]`
- [ ] **풀링 방식 (중요)**: PPO 5시드 + 벤치마크 = **6개 시계열을 동일한
      블록 인덱스로 공동 리샘플**. 시계열별 독립 추출이 아님
- [ ] 결정론적 재현 — SHA-256 기반 rng seed 파생

### 3.6.3 다중비교 보정

- [ ] Holm-Bonferroni, **비교 수 16** (정책 2 × 벤치마크 4 × fold 2)
- [ ] 보정이 왜 필요한지 (2장 §2.4와 연결)

### 3.6.4 정책 행동 진단 방법 ← **신설 여부 미정**

- [ ] `target_weights` 기준 분석임을 명시 (가격 변동 반영 전)
- [ ] 측정 지표 4종: ① 스텝 간 변화량 ② 시드 간 시간평균 배분 분산
      ③ Equal-Weight 대비 수익률 상관 ④ 드로다운 구간 vs 평시 현금 비중
- [ ] 드로다운 구간 정의 (15% 이상 낙폭)
