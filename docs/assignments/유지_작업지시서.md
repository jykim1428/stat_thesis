  구현 과정에서 여러 리뷰 라운드가 있었으나 **그 이력은 쓰지 않는다**
- ❌ "초기 구현이 train 통계를 train에 재적용하는 순환 검증 오류였다"
- ✅ "표준화 통계량은 학습 구간에서만 추정하며, 검증·평가 구간에는
  추정된 통계량을 적용한다. 전체 구간에서 통계량을 추정하면 평가 구간의
  분포 정보가 학습에 반영되는 데이터 누수가 발생한다"

## 3. 3.4 전통 벤치마크 모형 (3쪽)

**네 모형을 각각 0.5~1쪽씩.** 논문 표기는 용어사전 §7을 따른다.

| 코드명 | 논문 표기 |
|---|---|
| `buy_and_hold_btc` | **Buy & Hold BTC** |
| `equal_weight` | **Equal-Weight** |
| `markowitz` | **Minimum-Variance** ← Markowitz 아님 |
| `risk_parity` | **Risk Parity** |

### 각 모형에 써야 할 것

- [ ] **Buy & Hold BTC** — BTC 100% 매수 후 보유. 리밸런싱 없음 →
      turnover 0, 거래비용 0
- [ ] **Equal-Weight** — 자산 8종 각 1/8. 현금 비중 0
- [ ] **Minimum-Variance** — 수식 포함
      - Rolling window **720시간(30일)**, 매 시점 과거 720시간만 사용
      - 공분산: **Ledoit-Wolf shrinkage** (표본공분산 아님)
      - 개별 자산 상한 **30%** (`weight_bounds=(0, 0.3)`)
      - 기대수익률(μ) 추정 없이 **분산만 최소화**
      - 최적화 실패 시 equal-weight 폴백
- [ ] **Risk Parity (ERC)** — 수식 포함
      - 각 자산의 **위험 기여도(risk contribution)가 균등**해지는 비중
      - Minimum-Variance와 **동일한** window/shrinkage/weight_bounds 사용
        (두 벤치마크 간 방법론 일관성)
      - `scipy.optimize` SLSQP로 탐색, 실패 시 equal-weight 폴백
        (실제 실행에서 폴백 0회)
      - Inverse Volatility와의 차이: 본 구현은 공분산 전체를 반영하는
        엄밀한 ERC 정의

- [ ] **공통 사항** (절 끝에 한 문단)
      - 네 벤치마크 모두 PPO와 **동일한 OOS 날짜 범위**로 재실행된 값을 사용
      - 거래비용 0.1%를 `evaluate.py`에서 PPO와 **동일하게** 적용
      - 모든 전략이 **동일한 공용 평가 모듈**로 채점됨

**근거 파일** (docstring에 방법론이 이미 정리되어 있음 — 적극 활용)
- `experiments/benchmark_buy_and_hold_equal_weight.py`
- `experiments/benchmark_markowitz.py` ← docstring에 명칭 논의까지 있음
- `experiments/benchmark_risk_parity.py`
- `experiments/walk_forward_benchmarks.py` (OOS 재실행 스크립트)

**주의**
- Minimum-Variance를 "Markowitz"로 쓰지 말 것. `benchmark_markowitz.py`
  docstring에 이유가 설명되어 있다 — Minimum-Variance는 Markowitz
  Mean-Variance 프레임워크의 특수 케이스이며, μ 추정 없이 Σ에만 의존
- 성과 수치는 3.4에 넣지 않는다 (4장 소관). 여기는 **방법론만**
