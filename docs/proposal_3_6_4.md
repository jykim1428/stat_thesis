## 2. 왜 필요한가 — 문제 상황

### 문제 ①: 4.5의 측정 방법을 설명할 자리가 없다

4.5에서 다음과 같은 결과를 보고한다.

- 목표 비중의 스텝 간 평균 변화량 4.3×10⁻⁹ ~ 8.2×10⁻⁹
- Equal-Weight 대비 수익률 상관계수 0.999 이상
- 드로다운 구간과 평시의 목표 현금 비중이 소수점 6자리까지 동일

그런데 **이 값들을 어떻게 측정했는지**가 논문 어디에도 없다. 심사위원이
"이건 어떻게 잰 겁니까"라고 물으면 답할 근거 문단이 없다.

### 문제 ②: 분석 대상 선택이 결과를 좌우하는데 설명할 곳이 없다 ← 가장 중요

본 연구는 `target_weights`(정책이 지시한 목표 비중, 가격 변동 반영 전)로
진단했다. `weights`(가격 변동이 반영된 기말 비중)가 아니다.

**이 선택이 결론 자체를 바꾼다.** `weights`는 정책이 가만히 있어도 가격
변동 때문에 계속 흔들리므로, `weights`로 쟀다면 "정책이 고정 배분을
출력한다"는 결론이 나오지 않는다. 실제로 최초 구현은 `weights` 기준이었고
리뷰 과정에서 `target_weights`로 바로잡은 사항이다.

즉 **"왜 `target_weights`로 쟀는가"를 설명하지 않으면 4.5의 핵심 결과가
방법론적으로 성립하지 않는다.** 이걸 설명할 자리가 지금 없다.

### 문제 ③: 사후 변명처럼 읽힐 위험

현재 구조대로면 논문이 이렇게 읽힌다.

> 4.2~4.4에서 성과가 좋지 않다는 결과 → 4.5에서 갑자기 정책 내부를 분석

심사위원 입장에서는 **"결과가 나쁘게 나오니까 사후에 변명거리를 찾은 것"**
으로 보일 수 있다. 진단 방법을 3장에 미리 명시하면, 4.5는 사후 변명이
아니라 **설계 단계에서 계획된 분석**이 된다.

### 문제 ④: 3장-4장 대칭이 깨져 있다

| 4장 결과 | 대응하는 3장 방법 |
|---|---|
| 4.2 국면별 OOS 성과 | 3.6.1 성과 평가 지표 ✅ |
| 4.3 통계적 유의성 검정 | 3.6.2~3.6.3 ✅ |
| 4.4 정책망 비교 | 3.3 정책 네트워크 ✅ |
| **4.5 정책 행동 진단** | **없음** ❌ |

행동 진단만 대응하는 방법론 절이 없다.

## 3. 무엇을 쓸 것인가 (내용은 이미 확보되어 있음)

`experiments/walk_forward_behavior_diagnostics.py`에 측정 방법이 전부
구현·문서화되어 있어 **새로 실험할 것이 없다.** 아래를 서술만 하면 된다.

### (1) 분석 대상 정의
- `target_weights` = 정책이 지시한 목표 비중 (softmax 정규화 직후,
  가격 변동 반영 전, `env._actions_memory`)
- `weights` = 가격 변동이 누적된 기말 비중
- **`target_weights`를 쓰는 이유**: 정책이 "무엇을 하려 했는지"를 보려면
  가격 변동이 섞이지 않은 값이어야 한다

### (2) 측정 지표 5종

| 지표 | 내용 |
|---|---|
| 시간 불변성 | 목표 비중의 스텝 간 변화량 (평균·최대) |
| 집중도 | HHI — **현금 포함 9원소 기준(1/9=0.111)과 8자산 재정규화 기준(1/8=0.125) 둘 다** 계산. Equal-Weight 벤치마크가 현금 0%·8자산 균등이므로 기준을 혼동하면 안 됨 |
| 시드 간 이질성 | 시드별 시간평균 목표 배분의 분산 |
| 벤치마크 유사성 | Equal-Weight 대비 수익률 상관계수 및 tracking error |
| 방어 행동 | 15% 이상 낙폭 구간 탐지 후, 해당 구간과 평시의 목표 현금 비중 비교 |

### (3) 진단의 성격 명시
- 재학습·재탐색 없이 **저장된 backtest 결과만 분석**
- `locked_candidates.json`의 확정 후보를 그대로 사용
- 결과를 바꾸기 위한 재튜닝이 아니라 **원인 설명을 위한 분석**
  → 이 문장이 freeze 원칙과의 정합성을 보여준다

**근거 파일:** `experiments/walk_forward_behavior_diagnostics.py` (docstring에
방법론과 판단 근거가 이미 정리되어 있음), `results/walk_forward_behavior_diagnostics/diagnostics.json`

## 4. 대안 비교

| 방안 | 장점 | 단점 |
|---|---|---|
| **A. 3.6.4 신설** (건의안) | 방법/결과 분리, 사후 분석 오해 방지, 3-4장 대칭 회복 | 절 1개 증가 |
| B. 4.5 도입부에서 설명 | 절 수 유지 | 4장에 방법론이 섞임, 사후 분석으로 보일 위험 잔존 |
| C. 3.8로 독립 신설 | 3.6("평가지표·유의성검정")과 성격이 다르다는 점 반영 | 3장 절이 하나 더 늘어남 |

**건의: A안.** 단, 3.6의 제목이 "평가 지표 및 통계적 유의성 검정"이라
행동 진단과 성격이 다르다는 지적이 있으면 **C안(3.8 독립)도 수용 가능**.
핵심은 **진단 방법론이 3장에 있어야 한다**는 것이고, 번호는 부차적이다.
